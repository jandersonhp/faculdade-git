AULA 7

🗄️ Ciclo de Vida de um Banco de Dados

O desenvolvimento de um banco de dados acompanha o ciclo completo da engenharia de software, desde o levantamento de requisitos até sua evolução em produção.

⚠️ CAI MUITO NA PROVA: Estudo Inicial → Projeto → Implementação → Testes → Operação/Manutenção

1. Estudo Inicial

  • Levantamento de requisitos
  • Definição do escopo
  • Identificação de riscos
  • Regras de negócio
  • Fronteiras do sistema

2. Projeto do Banco de Dados

Projeto Conceitual
Modelo abstrato independente do SGBD.
Escolha do SGBD
Seleção da tecnologia ideal.
Projeto Lógico
Conversão do DER em tabelas.
Projeto Físico
Scripts SQL, índices e restrições.

3. Implementação e Carga

  • Instalação do SGBD
  • Execução de scripts
  • Conversão histórica de dados
  • Migração de dados antigos

4. Teste e Avaliação

  • Testes de integridade
  • Testes de segurança
  • Testes de desempenho
  • Consultas pesadas

5. Operação e Manutenção

  • Banco entra em produção
  • Backups
  • Monitoramento
  • Otimização de índices
  • Evolução estrutural

🧠 Estratégias de Modelagem

TOP-DOWN

Parte da visão geral do negócio para o detalhamento dos atributos.

  • Entidades primeiro
  • Atributos depois
  • Ideal para sistemas complexos

BOTTOM-UP

Parte dos atributos isolados até formar tabelas.

  • Atributos primeiro
  • Tabelas depois
  • Ideal para sistemas pequenos

MIDDLE-UP-DOWN

Técnica híbrida onde o projetista alterna entre visão macro e microatributos.

⚠️ PEGADINHA: Bottom-Up começa pelos atributos.

📚 Dicionário de Dados (Metadados)

Documento oficial que descreve tabelas, colunas, tipos de dados, PKs, FKs, limites e permissões.

Metadados: Dados sobre os dados.
AULA 8

📐 UML (Unified Modeling Language)

Linguagem gráfica internacional usada para visualizar, especificar e documentar sistemas.

⚠️ UML NÃO é linguagem de programação.

Relacionamentos

Associação

Ligação estrutural simples.

Agregação

Relação todo-parte.

Dependência

Mudança afeta outro elemento.

Diagramas UML

Casos de Uso Interação usuário/sistema
Classes Estrutura estática
Sequência Ordem temporal
Atividades Fluxo do processo
Estado Status do objeto
Implantação Servidores e hardware
AULAS 9, 10 e 11

🧩 Normalização & Dependência Funcional

Objetivos da Normalização
  • Reduzir redundância
  • Evitar anomalias
  • Melhorar integridade
  • Economizar espaço

Classificação dos Atributos

Atômico

Indivisível

Ex: CPF
Composto

Divisível

Ex: Endereço
Monovalorado

Um valor

Ex: Matrícula
Multivalorado

Vários valores

Ex: Telefone
Derivado

Calculado

Ex: Idade

Dependência Funcional

X → Y

X determina o valor de Y.

Total

Depende da PK inteira.

Parcial

Depende de parte da PK.

Transitiva

Depende de outro campo não-chave.

Formas Normais

1FN
  • Campos atômicos
  • Sem listas internas
  • Sem grupos repetidos
Telefones vão para outra tabela.
2FN
  • Estar na 1FN
  • Sem dependência parcial
3FN
  • Estar na 2FN
  • Sem dependência transitiva
  • Sem atributos derivados
4FN
  • Sem dependências multivaloradas
  • Evita redundância combinatória
